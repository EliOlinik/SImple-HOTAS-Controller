# T02–T05 – Phase 2 enumeration (done)

## Added
- Core: `HidUsage`, `HidNode`, `GameController`, `IHidNodeSource`, `IDeviceService`, `GameControllerGrouper`, `InstanceIdParser`.
- Win32: `DeviceEnumerator` (SetupAPI/CfgMgr32, read-only), `HidUsageReader` (zero-access CreateFile + HidP_GetCaps), `DeviceService` (enumerator + grouper).
- `tools/HotasController.Dump` – console dump; run `dotnet run --project tools/HotasController.Dump` (no admin needed).
- Tests: `InstanceIdParserTests`, `GameControllerGrouperTests` (17 tests total, all passing).

## Verified
- 34 present HIDClass nodes, identical to `Get-PnpDevice -Class HIDClass -PresentOnly`.
- Found 3 controllers: DualSense (054C:0CE6), X-56 Rhino Stick (0738:2221), X-56 Rhino Throttle (0738:A221), grouped under their USB device with product-string names.

## Known gaps / notes for Phase 3–4
- The disabled-device path (usage unreadable, recognised via "game controller" name) is covered by unit tests only; it has not been run against a real disabled controller.
- Group nodes include the "USB Input Device" (usbhid) nodes and the HID\ children. Phase 4 must decide whether to disable the USB device itself or its HID nodes.
- `pnputil /enum-devices /class HIDClass` printed nothing for "Instance ID" in this locale; use `Get-PnpDevice` for cross-checks.
- Bluetooth HID IDs (`HID\{guid}_VID&...`) are not parsed for VID/PID yet; such controllers would show without VID:PID.
- CsWin32 notes: `SetupDiGetClassDevs` returns a raw `HDEVINFO`, wrapped into `SetupDiDestroyDeviceInfoListSafeHandle`; `CM_Get_Device_IDW` is the name to list in `NativeMethods.txt`.
